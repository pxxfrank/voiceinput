# 性能测试报告

> 测试日期：2026-10-20
> 原始数据：`docs/perf-results.json`
> 测试脚本：`scripts/perf_harness.py`

## 1. 测试环境（重要）

| 项 | 值 |
|---|---|
| 设备 | QEMU 虚拟机（**不是**目标 ThinkPad X1 Carbon Gen 12） |
| 系统 | Windows 10 19045 x64（**不是** Windows 11） |
| CPU | Intel Xeon Gold 6230N，36 物理核 / 36 逻辑核 |
| 内存 | 64 GB |
| GPU/NPU | 无（QEMU）；所有推理使用 CPU |
| 权限 | 非管理员 |
| 音频 | 仅 RDP 重定向音频（无物理麦克风） |

因此，本报告数据只能代表“当前虚拟机上的真实测量”，不能冒充目标硬件的性能。
目标硬件（Ultra 7 155H / Intel Arc / NPU）上的性能未验证。

## 2. 方法

- 使用真实 WAV（流式模型 4 段 + SenseVoice 5 段，含中英混排）。
- 以 100 ms 为单位按实时速率喂入，测量：
  - **首字延迟**：VAD 判定语音开始 → 第一次出现非空 partial。
  - **更新间隔**：相邻 partial 的时间差。
  - **RTF**：`StreamingSession.decode_seconds / 音频秒数`（纯解码 CPU 时间，不含实时 sleep）。
  - **复核延迟**：SenseVoice 单次解码耗时。
  - **LLM**：llama.cpp 非流式精修总耗时；另用 SSE 测首 token。
  - **CPU**：`time.process_time()` / 墙钟；结果表述为“单核百分比”，除以 36 核即为整机占用。
  - **内存**：`GetProcessMemoryInfo` 工作集；LLM 为 llama-server 子进程。
- 所有数字来自实际运行，未使用构造字符串或模拟结果。

## 3. 结果

### 3.1 流式识别

| 指标 | 目标 | 实测 P50 | 实测 P95 | 结论 |
|---|---:|---:|---:|---|
| 首字延迟 | ≤800 ms | **968 ms** | 1173 ms | ❌ 未达标 |
| partial 更新间隔 | 100–300 ms | **242 ms** | 365–1213 ms | ✅ P50 达标；停顿/端点处 P95 超 300 |
| ASR RTF | ≤0.3 | **0.15** | 0.18 | ✅ 达标 |

- 首字延迟受 480 ms 模型固有延迟 + VAD 60 ms + 80 ms partial 节流影响。
- 同系列 160 ms 模型实测首字 805 ms，但 RTF 0.35、识别质量下降（“礼拜二”→“篱 Ba”），故未采用。
- 目标硬件未验证；若必须满足 800 ms，可考虑 160 ms 模型或更激进 VAD，但需接受精度/CPU 代价。

### 3.2 复核 ASR

| 指标 | 实测 |
|---|---:|
| 复核延迟 P50 | 321 ms |
| 复核延迟 P95 | 510 ms |
| 复核 RTF | 0.03–0.06 |

超时默认 2.0 s；超时/忙时回退到流式结果。复核不是无条件覆盖。

### 3.3 本地 LLM

| 指标 | 目标 | 实测 |
|---|---:|---:|
| 首 token | — | 264 ms |
| 完整精修 P50 | 尽量 ≤1–2 s | **2660 ms**（2246–2661 ms） |
| 模型加载（预热后） | — | 4.0–6.0 s |
| 模型加载（冷启动） | — | 10.5 s |
| 推理设备 | CPU | CPU |
| 线程 | — | 12（本机自动；目标机按 `cpu/3` 自动） |

精修耗时略超 1–2 s 目标；在 2B/CPU 条件下属于可接受范围，但应如实标记为未完全达标。
精修在独立 worker 执行，不阻塞采集/UI/流式识别。

### 3.4 内存

| 模式 | 实测 | 目标 | 结论 |
|---|---:|---:|---|
| 基础（ASR+复核，无 LLM） | **559 MB** | 争取 ≤1.5 GB | ✅ 达标 |
| 智能（额外常驻 LLM） | 主进程 559 MB + llama-server 1970 MB ≈ **2.53 GB** | 争取 ≤1.5 GB | ❌ 超出 |

说明：基础模式满足目标；智能模式因 2B GGUF 权重常驻而超出。
设置中可关闭 `preload`，让 LLM 按需加载/空闲卸载；基础功能不受影响。

### 3.5 CPU

| 指标 | 实测 |
|---|---:|
| 流式识别进程 CPU | 126–155%（单核百分比） |
| 折算整机占用（36 核） | 约 3.5–4.3% |
| 目标 | 持续 ≤25% |

按整机口径达标；目标硬件核数更少，实际百分比会更高，未在目标机验证。

### 3.6 加载时间

| 模型 | 实测 |
|---|---:|
| 流式 ASR | 8.5 s |
| 复核 ASR | 2.7 s |
| LLM（冷） | 10.5 s |
| LLM（热） | 4.0–6.0 s |

启动时后台加载，不阻塞托盘/热键注册；模型未就绪时按热键会提示而不是静默失败。

## 4. 未验证 / 未达标

- 首字延迟未达 800 ms（P50 968 ms）。
- LLM 精修 P50 2.66 s，高于 1–2 s 目标。
- 智能模式内存 2.53 GB，高于 1.5 GB 目标（基础模式 559 MB 达标）。
- 目标硬件（ThinkPad X1 Carbon Gen 12 / Windows 11 / Arc / NPU）未测试。
- 连续 3 小时稳定性未测试（仅做了多轮会话与重复 E2E）。
- 真实物理麦克风未测试（仅有 RDP 音频设备）。
- OpenVINO / iGPU / NPU 加速未实现或验证；当前仅 CPU。

## 5. 复现

```powershell
.venv\Scripts\python.exe scripts\perf_harness.py
```

会重新生成 `docs/perf-results.json`。测试会启动本地 llama-server，结束后由看门狗回收。
